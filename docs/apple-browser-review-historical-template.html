Account required
No Proteus account is required to browse websites. Optional AI providers and third-party websites use their own accounts.

Browser behavior

  • Home offers a website address or search field.
  • HTTP and HTTPS URLs open directly in new browser tabs.
  • Address bar, back/forward history, tab duplication and separate browser profiles are available.
  • External website links wait for startup restoration, then open as human-owned tabs without agent access.
  • Users control extension installation and website permissions.

WebAuthn evidence

  • Embedded Chromium successfully creates a credential and signs in using a simulated CTAP2 USB security key.
  • The test verifies signature, challenge, origin, relying-party hash and presence/verification flags.
  • An unrelated relying-party request is rejected.
  • This test does not prove physical security-key, Touch ID or iCloud Keychain integration.

Review walkthrough

  1. Launch the app in a clean macOS test account after distribution signing is completed. No evaluation login is needed for browser features.
  2. From Home, enter a website URL or search term and choose Open. Use the address bar to navigate to another site and test back/forward.
  3. Use macOS Open With to open an HTTP/HTTPS link in Proteus. It should display the requested website in a new tab.
  4. Close all Proteus windows and open another link. A browser window should reopen.
  5. For WebAuthn, use a test relying party and a disposable security key; do not use a production account. The supplied evidence documents the automated virtual-authenticator acceptance.

What we are requesting from Apple

We plan to integrate the browser WebAuthn implementation with iCloud Keychain for both saving new passkeys and signing in with existing passkeys, using Apple's authentication and consent UI. We are preparing a request for the macOS web-browser public-key credential entitlement.

The official iCloud Passwords extension currently cannot connect to Apple's native helper from Proteus. Native pipe failure handling has been repaired, but Apple authorization and an accepted iCloud integration are separate requirements. We do not claim Apple approval or working iCloud pairing.

Electron 44.5.1 exposes Touch ID configuration but not the newer platform-passkeys option. Native iCloud integration remains implementation and acceptance work following the approved entitlement path.
